# 企业微信本地视觉自动化：总体架构

## 1. 目标与边界

本项目是一个运行于用户桌面的辅助工具：在已登录的企业微信桌面客户端中，通过**本地屏幕截图、OCR、鼠标、键盘与剪贴板**完成一对一外部联系人消息发送。

第一阶段（Windows MVP）只支持单条纯文本任务，且每次发送均要求操作者在本机明确确认。

本项目不做以下事情：

- 不调用企业微信服务端 API；
- 不修改、注入、逆向或读取企业微信客户端内存；
- 不处理验证码、风控提示或登录异常；
- 不做无人值守批量发送、自动加好友或自动回复；
- 不将截图、联系人姓名或消息正文上传到云端。

遇到联系人无法唯一确认、OCR 置信度不足、窗口状态异常或平台提示限制时，任务必须停止并进入人工处理状态。

## 2. 架构原则

1. **本地优先**：图像、OCR 模型、任务数据与审计记录均在设备本地处理。
2. **平台隔离**：业务流程不依赖 Windows/macOS 的具体输入或截图实现。
3. **先验证、后操作**：每次可能影响收件人的操作前都需要可观测证据。
4. **默认安全失败**：不确定即失败；绝不根据模糊 OCR 结果向候选联系人发送。
5. **全程可审计**：记录任务状态、操作者确认、非敏感诊断信息与脱敏证据。

## 3. 组件与职责

```text
桌面界面（Tauri + React）
    ├── 创建任务、显示预览、获取确认
    └── 查看任务历史、失败原因与脱敏证据
                │ IPC
自动化核心（Rust）
    ├── 状态机与取消/超时/重试
    ├── 联系人精确匹配与置信度策略
    ├── 发送前、后双重核验
    └── 审计记录与幂等保护
        ┌───────┴────────┐
本地视觉层              平台适配层
    ├── 局部截图裁切        ├── 截图与显示器坐标
    ├── OpenCV 预处理        ├── 窗口前台化
    ├── PaddleOCR 推理       ├── 鼠标与键盘事件
    └── 文本框/置信度         └── 剪贴板
```

> 图中所有 OCR 输入只来自本机屏幕，视觉层不得发起网络请求。

## 4. 模块边界

| 模块 | 责任 | 不负责 |
| --- | --- | --- |
| `desktop-app` | 任务编辑、人工确认、状态展示 | 发送决策与系统输入 |
| `automation-core` | 状态机、证据判断、失败收敛 | 操作系统 API、OCR 实现 |
| `vision` | 图像预处理、OCR、文字位置与置信度 | 鼠标点击、业务规则 |
| `platform-windows` | 屏幕捕获、焦点、鼠标、键盘、剪贴板 | 姓名匹配或 OCR |
| `storage` | SQLite、加密、审计、清理策略 | 屏幕或输入操作 |

macOS 将以 `platform-macos` 实现同一组平台端口；自动化核心与视觉层不因平台改变。

## 5. Windows MVP 状态机

```text
Draft
  → LaunchingClient
  → WaitingForClient
  → SearchingContact
  → VerifyingCandidate
  → VerifyingChatHeader
  → PreparingMessage
  → AwaitingHumanConfirmation
  → Sending
  → VerifyingDelivery
  → Completed

任意状态 → NeedsHumanReview | Failed | Cancelled
```

关键约束：

- 进入 `Sending` 前，联系人搜索结果与聊天页标题均须与目标名称精确匹配；
- `AwaitingHumanConfirmation` 仅接受当前操作者在界面中的一次明确确认，确认有短时有效期；
- `VerifyingDelivery` 只验证“本次消息内容出现在当前已核验聊天区”，不把网络送达当作可保证的结果；
- 超时、失焦、窗口被替换、OCR 结果冲突、风控或登录界面出现时，转 `NeedsHumanReview`。

## 6. 视觉定位策略

1. 优先使用经过标定的局部区域，不扫描整屏；
2. 对联系人候选区和聊天标题区进行独立 OCR；
3. OCR 输出需包含文字、边界框、置信度和截图指纹；
4. 姓名匹配默认逐字精确匹配；别名规则必须由企业管理员显式配置；
5. 目标坐标在点击前重新计算，并要求窗口、分辨率、缩放比例与当前标定一致；
6. 低置信度、多个精确匹配或文字框过于接近时，拒绝点击。

## 7. 数据与审计

SQLite 只保存执行任务必需的数据。消息正文默认不长期保存；审计记录存储消息摘要（长度、哈希、时间）而非全文。失败截图须局部裁切并脱敏，设置可配置的自动清理期限。

每条审计记录至少包含：任务 ID、操作者、平台、企业微信版本（若可获得）、状态转换、确认时间、失败代码和证据引用。不得记录剪贴板原文、账号令牌或完整聊天历史。

## 8. 权限与发布

- Windows MVP 仅在交互式已解锁的桌面会话中运行；
- 程序需要明确提示用户：发送期间请勿切换窗口或操作鼠标键盘；
- 后续 macOS 版本首次启动时，需要引导授予“辅助功能”和“屏幕录制”权限；
- 所有构建产物签名发布，模型与依赖清单可追溯。

## 9. MVP 验收条件

Windows 测试设备上，以专用测试账号和测试外部联系人验证：

1. 可定位已打开且前台的企业微信；
2. 能以 OCR 找到唯一的测试联系人并完成双重姓名核验；
3. 操作者确认后才能粘贴与发送一条纯文本消息；
4. 能在聊天区识别到本条消息作为界面完成证据；
5. 出现同名、识别失败、失焦或登录/限制提示时不会发送，并会留下可读失败原因。
